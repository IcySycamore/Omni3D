# 设计规范（Omni3D 面板）

> **给改 UI 的人（和 AI）看的。** 每次动样式前先读这一页。
> 这份文档的存在理由：这个面板的样式曾长期"改一处加一个新值"，最夸张时
> **圆角有 19 种、字号有 24 种、padding 有 44 种** —— 接近 100 个随手写的数字。
> 那不是配色问题，是**没有体系**，看起来就不像正经产品。
>
> 现在所有值都收敛成 token（定义在 `panel/index.html` 的 `:root`）。
> **CSS 里不该再出现裸数值。**

---

## 一、基调

**新拟物（Neumorphism / Soft UI）** —— 整块面板是**一个**台面，控件靠双向投影「凸起」或「凹陷」。

- 界面**退到后面**，内容（点云、模型）是主角
- **所有面共用同一个底色**（`--neu-base`）：卡片、按钮、面板、浮层的 `background` 都读它，
  **层次只由阴影（凸起/凹陷）与文字明度拉开**，不再靠「一层比一层亮」
- 描边**恒定透明**（`--glass-border`）：面的边界交给阴影，不再用线
- **颜色只用在状态**（选中 / 危险 / 成功 / 警告）；大面积一律是台面色
- 不用装饰性动效；动效只用来解释「状态变了」

> ⚠️ **同色的面必须配阴影，否则等于隐形。**
> 新拟物的底都一样、描边又全透明，一个「有底色但没阴影」的面就是台面上一块脏斑。
> `.hamburger` 踩过：它已经在凸起分组里，却还留着旧调色板的 `background: #141624`
> （比台面还暗），出来就是一块黑斑。新加面层时先回答：它**凸起**还是**凹陷**？
> 然后挂 `--neu-raised*` / `--neu-inset*`。

> ⚠️ **鼠标划过「抬起来」用 `transform: translateY(-1px)`，不要改 padding/尺寸**（会抖）。

### 明确不要

| 不要                                       | 为什么                                                                                                 |
| ------------------------------------------ | ------------------------------------------------------------------------------------------------------ |
| **「青 → 紫」这类渐变做按钮/进度条**       | 用户原话：「像蓝莓一样…ai 风格太浓」。已彻底删除，别再引入                                             |
| **主色当大面积填充**（按钮底、大片色块）   | 同一支青做 5px 指示点很好看，糊成一整块按钮底就刺眼（实测平均饱和度 0.86）。**面积**才是问题，不是色相 |
| 装饰性渐变、发光边框、大面积毛玻璃叠毛玻璃 | 视觉噪音；毛玻璃只在需要"透出背景"的地方用一层                                                         |
| 用颜色区分"重要/次要"                      | 用**字重 + 明度**；颜色留给状态（选中/危险/成功）                                                      |
| 悬浮提示写整句话                           | 见第四节「文案」                                                                                       |
| 图标用字符（`◈` `↺` 之类）                 | 字形随平台字体变；一律自绘 SVG                                                                         |

## 二、Token 全表

定义在 `panel/index.html` 的 `:root`（**与主题无关的部分只定义一次**）。

### 颜色

| 分组 | Token                                                                    | 用途                                                                                                              |
| ---- | ------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------- |
| 台面 | `--neu-base` `--neu-light` `--neu-dark`                                  | 唯一底色，以及做投影用的亮/暗两色（亮在左上、暗在右下）                                                           |
| 底组 | `--bg-deep` `--bg-elevated` `--bg-card` `--bg-card-hover` `--bg-sidebar` | **全部等于 `var(--neu-base)`**；名字只为语义，别再给它们各写一个色                                                |
| 描边 | `--glass-border`                                                         | **恒定透明**：面的边界交给阴影，不再用线（`--glass-border-active` 已删：旧设计里 hover/焦点靠主色描边）           |
| 文字 | `--text-primary` `--text-secondary` `--text-muted`                       | 三级，够用（`--text-faint` 已删：只被一个缩略图占位用到，却从未定义过）                                           |
| 主色 | `--accent-cyan` + `--accent-faint/wash/glow/edge`                        | 青管**动作**。只上小面积：图标 / 指示点 / 进度条 / 描边 / 选中态                                                  |
| 语义 | `--danger` `--success` `--warning`                                       | 只表达状态，**不拿来填面**                                                                                        |
| 填充 | `--fill-1..4`                                                            | **不透明的**台面邻近色（比台面略亮一点），给按钮/标签一点点底色差；旧的半透明写法在新拟物下会透出台面、看不出深浅 |

> **主色的面积规矩（同一个地方踩了两次）。**
> 先是「青 → 紫」渐变被嫌 ai 味重；删成纯色后**更糟** —— `#22d3ee` 糊成
> 一整块按钮底，用户原话「这个青色太丑陋，还不如原来」。可见问题在**面积**，
> 不在色相：同一支青做 5px 指示点、图标、进度条、描边都很好看。
>
> 落地方式：主按钮的底走台面色 `--fill-1` + `--neu-raised` 凸起 + 一圈 `--accent-faint` 外环，
> `--accent-cyan` 用在**文字**上，主操作靠字重与凸起认出，不靠色块。
> 实测 `.view-task-btn` 区域平均饱和度 0.86 → 0.37；
> 同屏的「删除」也是描边语言，两者才终于是一套。
> 守卫：`test_primary_button_is_not_a_slab_of_accent`。
> （`--on-accent` 因此废弃删除。）

### 圆角（六档）

`--r-xs` 4 · `--r-sm` 6 · `--r-md` 8 · `--r-lg` 12 · `--r-xl` 16 · `--r-full` 999

> 选档口诀：输入框/小按钮 `sm`、常规按钮 `md`、卡片 `lg`、浮层 `xl`、药丸形 `full`。
> **不要为了"看起来差不多"新造一档** —— 差 1px 没人看得出来，但十种值堆起来就散了。

### 字号（七档）

`--fs-xs` 11 · `--fs-sm` 12 · `--fs-base` **13（正文默认）** · `--fs-md` 14 ·
`--fs-lg` 15 · `--fs-xl` 17.6 · `--fs-2xl` 20.8 · `--fs-3xl` 44.8（px 折算）

### 间距（九档）

`--sp-1` 2 · `--sp-2` 4 · `--sp-3` 6 · `--sp-4` **8** · `--sp-5` 12 ·
`--sp-6` **16** · `--sp-7` 20 · `--sp-8` 24 · `--sp-9` 32

> 只有这九档（基本是 4 的倍数）。`--sp-4` 是**控件内边距**的默认档，
> `--sp-6` 是**卡片内边距 / 区块间距**的默认档。
> **不要为了"看上去正对齐"新造一档** —— 1px 的差别肉眼看不出来，
> 但十几种值堆起来就是"没设计过"。
> 允许的例外：`0` / `auto` / `calc()`。

### 其它

| Token                                                      | 说明                                                          |
| ---------------------------------------------------------- | ------------------------------------------------------------- |
| `--neu-raised` `--neu-raised-sm`                           | **凸起**：亮影在左上、暗影在右下；常规面 / 小控件             |
| `--neu-inset` `--neu-inset-deep`                           | **凹陷**：按压态、选中态、视口这种「挖进去」的面              |
| `--shadow-card` = `--neu-raised`                           | 组件默认凸起；**一张卡只用一个阴影**                          |
| `--shadow-lift` `--shadow-glow`                            | 浮层（模态/悬浮面板）/ 进度条。这是**真投影**，不要往面层上用 |
| `--transition-fast` 0.16s / `--transition-smooth` 0.28s    | 就这两档                                                      |
| `--font-mono`                                              | 数字、坐标、代码                                              |
| `--radius` 系列                                            | **已废弃**，见 `--r-*`                                        |
| `--viewer-bg` `--star-opacity` `--logo-filter` `--overlay` | 给 JS 读 / 需随主题反转                                       |

## 三、主题

- 主题**只覆盖变量**，不碰任何组件规则。加主题 = 在 `:root[data-theme="…"]` 加一段。
- **新拟物要求每个主题至少写全三组**：① `--neu-base/light/dark`（台面 + 两道阴影）；
  ② **不透明**的 `--fill-1..4`；③ 三级文字色。
  ⚠️ 漏了 ① 的后果是真实的：切到浅色时 `--neu-light/--neu-dark` 还是 `:root` 的
  深色值，白底上冒出两道**黑**阴影（用户原话「阴影问题巨大」）。
  ⚠️ 漏了 ② 更隐蔽：半透明填充会透出台面，hover / 选中 / 按下的深浅差被吃掉，
  三种状态全都看不出来。
  `--bg-*` **不用写**：`:root` 里它们已经全是 `var(--neu-base)`，主题再写只是重复定义。
  守卫：`test_every_theme_declares_its_own_surface_colors`（三色必须是字面色值且彼此不同）
  - `test_every_theme_has_opaque_fills`。
- 挂在 **`html`** 上（`html, body` 的 background 都读 `html` 上的变量，挂 body 盖不住）。
- **每个主题必须写全**：`--accent-faint/wash/glow/edge`（漏了会退回 `:root` 的青色，
  在暖色主题里冒出青光）、`--logo-filter`、`--overlay`、`--star-opacity`。
  （`--on-accent` 已随主按钮改中性面而删除，不再需要。）
- **❌ 不许写死 `color: #fff`。** 浅色主题下那就是白字白底（看不见）。
  实测踩过 `.hotkey-input`：用户报「切到明亮时看不到快捷键了」就是它。
  要「更亮一档」写 `--text-primary`。
- **3D 视口在所有主题里都保持深色**：点云的"按高度着色"是蓝→白渐变，放浅底上看不见。

## 四、文案

- **UI 里不出现实现原理**（公式、引擎名、端口、矩阵）。
- **括号里的解释一律去掉**（"总是执行选定操作（不再弹窗）" → 去掉括号）。
- **悬浮提示（`title`）只给名称**。详细说明归**帮助模式**（它读 `data-help`）。
  ⚠️ 最容易破坏这条的是"动态改 title"（`updateViewButtons()` 干过），改前先看
  `paintToolbarIcons()`。
- **不知道点什么会怎样，就用状态表达**（`.satisfied` 高亮），不要挂一句话解释。
- 帮助文档在 `panel/assets/help.html`，改完刷新即生效。

## 五、图标

- **一律自绘 SVG**，纯描边、`stroke="currentColor"`（复用 `_SVG_OPEN`）。
- 尺寸由 CSS 定，不要在 SVG 上写死 width/height（见「按钮里的图标」那一节）。
- **❌ 一律不用字形图标**（`☰ ◈ ✕ ✓ ↑ ↓ ● 🗑 📷` …）。它们的粗细与形状由
  **运行环境的字体**决定 —— 同一排按钮换台机器就长得不一样，还会被当成 emoji。
  守卫 `TestUiIconsAreSvg::test_no_glyph_is_assigned_as_button_text`。
- **一个图标只能有一个来源。** 元信息条踩过：HTML 里写死一个 emoji 图标，
  而 9 个调用方又各自在文字前面再拼一个 → 同一个图标画两遍（用户：
  「一个重复的非svg图标」）。现在图标由 `META_ICONS` 按 `kind` 一处提供，
  文字走 `textContent`（顺带避免拼接 HTML —— 文件名里可能带 `<`）。
- **静态按钮**：HTML 里留 `<span class="btn-ic" data-icon="x"></span>` +
  `<span class="btn-text">文字</span>`，由 `paintUiIcons()` 统一填。
  ⚠️ **不要再写 `btn.textContent = "● 录制"`** —— 图标和文字挤在同一个字符串里，
  改一次文字就得把图标再拄一遍。要改就用 `setBtnText()` / `setBtnIcon()`。
  ⚠️ 图标表**拿不到 key 是静默跳过的**，所以三张表都要有守卫：
  `test_ui_icon_map_has_no_orphans`（用了却没有 / 画了却没人用）、
  `test_every_nav_page_has_an_icon`、`test_every_toolbar_button_has_an_icon`。
  侧栏「推广」就是这么带着 📣 活了好几版的。
- ⚠️ **`const` 没有变量提升 —— 图标表的声明顺序不能乱。** `UI_ICONS` 引用了
  `NAV_ICONS`/`META_ICONS`/`TOOLBAR_ICONS`，必须排在它们之后。
  实测把它插到 `META_ICONS` 前面 → 模块求值抛 `ReferenceError`，
  **整个初始化中断**（图标全空、设置页 tab 点不动），而 `node --check` 只查语法。
  守卫：`test_icon_maps_are_declared_in_dependency_order`。
- 换掉一个 emoji 时，**把它传达的信息也接住**：「录制中」那个红色圆点换成
  自绘图标后，红是靠 `.meta-info-bar[data-kind="record"]` 补回来的。
- **画之前先确认"它要像什么"**：侧栏「设置」原来画的是"中心圆 + 虚线环"，
  用户第一眼问「这是齿轮吗？？」—— 既不像齿轮也不像设置，现在改成滑杆。
  **虚线圆环极易被误认**（光圈/齿轮/加载），能不用就不用。

## 六、交互状态

四种状态都要有，**不能只做 hover**：

| 状态             | 做法                                                                                                                                                  |
| ---------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| `:hover`         | 只改**阴影/底色**（凸起更强一档，或 `--fill-1` → `--fill-2`），可加 `translateY(-1px)`「抬起来」；**不改 padding/尺寸**（改了会抖）                   |
| `:active`        | `scale: 0.96`（项目里已有）或底色再深一档                                                                                                             |
| `:focus-visible` | **必须有**：`outline: 2px solid var(--accent-cyan)` + `outline-offset: 2px`。键盘用户靠它导航；鼠标点击不显示（靠 `:focus:not(:focus-visible)` 清掉） |
| `:disabled`      | `opacity: .4` + `pointer-events: none`                                                                                                                |

> 改动前整个界面**没有一套自己的焦点样式**：按钮用浏览器默认焦点框（颜色粗细
> 与主题无关），输入框是 `outline: none` + 自己画的一套。键盘用户在一排纯图标
> 按钮之间看不出焦点在哪。

### 测量引导：先分清「量点集」还是「量一个环」

|                       | 面积（`polygon_area`）           | 体积（`polyhedron_volume`）                  |
| --------------------- | -------------------------------- | -------------------------------------------- |
| 量的是什么            | 这些点围出的**多边形**（边界）   | 这些点的**凸包**（与连线无关）               |
| 顶点度数              | 恰好 2 —— 边界本来就是这样      | **不限制**（三棱柱每顶点是 3）               |
| 落点时自动连线        | 连上一点                         | **不连**                                     |
| 「完成」              | 自动收口 + 校验闭环              | **不收口**（没有环）                         |
| 引导线                | 橡皮筋 + 收口虚线                | 只有悬浮环                                   |
| 骨架怎么画            | 点按序连起来                     | `measurement.outline`（服务端给的凸包棱）    |

> 判据只有一处：`RING_OPS`（`panel/index.html`），且用 **op** 而不是工具名 ——
> op 才是「算的是什么东西」。
>
> ⚠️ 别把「每顶点最多两条边」当通用规则：那是**多边形边界**的语义。拿它卡体积，
> 三棱柱（每顶点度数 3）会被判成不合法 —— 用户原话「体积引导不应该限制顶点度数」。
>
> ⚠️ 骨架不许前端自己算：体积由服务端算 `ConvexHull`，棱必须出自**同一个**凸包
> （`server/core/geometry.py::convex_hull_edges`）。客户端另算一份就会出现「画出来的
> 不是算出来的」—— 用户当时的话是「现在测的是什么不清楚」。
>
> ⚠️ 凸包的面是**三角化**的：直接取 `simplices` 的边，立方体会多出 6 条面内对角线
> （18 条、度数 4），画出来就是「一堆斜线」。先按支撑平面合并三角片，再取每个面
> 只被一个三角片用到的边。

### 常驻状态栏 / 测量条目 / 两点工具

- **状态栏只报当前进度，不写操作说明。** 整句操作说明属于帮助内容（`data-help`）；
  做完一件事之后再把说明塞回来，就变成「已经做完了还在教你怎么做完」。
  ⚠️ 棕色的就绪文案**只能在真的够数之后**才写「可完成」：写着「可完成」却点不动，
  看起来就是按钮坏了（用户实测：面积只取 2 个点就已经显示「可完成」）。
- **两点工具量完要留下看得见的一段**：画线 / 尺度取完 2 个点随即连一条线段
  （尺度那条路没有测量帮忙落库，必须自己先 `persistCurrent()`，否则弹窗确认时的
  `reloadAnnotations` 会把刚画的线段丢掉）。
- **测量行的子元素默认折叠**（设置 → 行为「测量完成时折叠子元素」，默认开）。
  展开状态记在 `STATE.expandedMeasurements`（记的是**展开**，因为默认是折的）。
- **短工具（画线 / 尺度 / 三角形面积）的状态栏文案与面积 / 体积是同一套**：
  「至少要 N 个点」→「已取 N/M · 未完成」→「已取 N 个 · 可应用」。
  进度要把**落点引导**（`pending`）也算上 —— 只报列表选中集，就会出现「在视图里
  点了两个点，状态栏还在说还需 2 个点」。
- **标尺校准弹窗**（用户给的规格）：标题在左上；右上角**一个帮助 + 一个叉号**
  （帮助跳到帮助文档的「常见物品尺度」清单，锚点 `#scale-reference`）；两行
  **并列**（模型尺度 / 真实尺度 + 输入框）；右下角两个按钮（取消 / 完成）。
- ❌ **几何的 `color` 属性绝不能和我们自己的颜色快照共用同一个数组**：
  three 的 `BufferAttribute` 只是**引用**传进去的数组（不拷贝），而 `setColorMode`
  直接改写它 —— 共用一份就会在切到高度着色时把真彩色覆盖掉，之后再也切不回来
  （用户实测：「颜色只能切一次然后就卡死」）。两个创建点都必须 `.slice()`。
- 点云**没有真实颜色**时（服务端只回坐标），两种着色本来就是同一张图：
  颜色按钮要**置灰**，而不是让用户点了没反应。

## 七、加新样式时的检查清单

1. 这个值在 token 表里有对应档位吗？没有 → 用最接近的档，**别新造**
2. 圆角/字号/间距/颜色是**变量**吗？（CSS 里不该出现裸 px 的这几类值）
3. 要拿主色填**大面积**吗？**不行**（面积大了就刺眼）—— 改成台面色
   `--fill-*`，主色留给文字 / 图标 / 焦点环
4. 这个面**凸起还是凹陷**？凸起挂 `--neu-raised*`、凹陷挂 `--neu-inset*`。
   **漏了阴影的同色面 = 隐形**
   - 输入框这类「浅坑」用 `--neu-inset-soft`（2px/4px），
     不要直接上按压档 `--neu-inset`（3px/7px）—— 浅色主题下会看着像个洞
     ⚠️ 那条规则曾是一份**选择器白名单**（`.hotkey-input` / `.server-row input` …）：
     新写一个输入框忘了加进去，它就会退回浏览器默认外观（纯白底 + 黑字 + 灰描边 +
     Arial + 系统箭头），在新拟物台面上就是一块白板。实测过 —— 校准弹窗的输入框
     就是这样（读了计算样式才看出来：`background: rgb(255,255,255)`、`appearance: auto`）。
     现在**弹窗这一层改成按容器兜底**（`.modal-card input:not([type="checkbox"])`），
     白名单本身还在（其它地方的输入框仍靠它）—— 新写输入框先想清楚它落在哪一边
5. **hover 只有一种语言：抬起来**（底色微变 + `--shadow-lift` + `translateY(-1px)`）。
   ❌ 不写主色描边、❌ 不写发光（`0 0 20px var(--accent-faint)` 这类）
6. 是不是又在用颜色表示「选中」？新拟物里**选中 = 按下**（`--neu-inset`），
   颜色只在真的表达语义状态（危险/成功/警告）时才用
7. 信息是不是在同一个界面里说了两遍？输入框旁边的状态 tag 踩过：
   「未设置凭据」不过是把 placeholder 又说一遍 —— **优先减**
8. 加了 token？**必须同时在所有主题里写全**（有测试守着）
9. 加了新 token 却没人用 → `test_no_orphan_tokens` 会红
10. 新按钮要图标？先在 `UI_ICONS` 里画好，再用 `data-icon` 槽位 —— **不要拿字形当图标**
11. 改按钮上的文字？用 `setBtnText()`，**不要写 `btn.textContent = "● 录制"`**（会把图标抹掉）
12. 往图标表里加新表？**注意 `const` 没有变量提升**，引用了谁就得排在谁后面
13. 改测量引导？先确认这个工具量的是**点集**还是**环**（见上表），判据写进 `RING_OPS`；
    画骨架要用服务端给的 `outline`，别自己算
