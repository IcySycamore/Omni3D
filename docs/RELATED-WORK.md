# 相关工作与协议复用（WebODM / NodeODM / Potree / SuperSplat vs 我们的 panel）

> 写这份文档的原因：C# 重构前做技术选型时，需要回答两个问题 ——
> **① 市面上有没有可复用的开源面板/协议？② 哪些必须自己造？**
> 结论：**有可复用的协议形状，没有可复用的"官方服务商 + 计费"整条链路**。
>
> 配套：[`docs/HANDOVER.md`](HANDOVER.md)（§5.1 协议复用清单）、[`CONTEXT.md`](../CONTEXT.md)（领域词汇）。
>
> **按「panel 侧 / 服务侧」拆分过的版本**（新仓库开工用）：
> [`docs/handover/01-industry-research.md`](handover/01-industry-research.md)。

## 1. 五个对象的定位（别混为一谈）

| 对象             | 是什么                                                  | 与我们的关系                                                                            |
| ---------------- | ------------------------------------------------------- | --------------------------------------------------------------------------------------- |
| **WebODM**       | 航测（SfM/MVS）**项目管理面板**，Django + DRF，AGPL-3.0 | 服务端形态最像我们（服务商 + 面板 + 队列 + 账号），但路线是正射/DSM，且**没有计量计费** |
| **NodeODM**      | **处理节点 REST API**（无 GUI），AGPL-3.0               | **重建域的事实标准协议**；WebODM 就是它的客户端。我们的 `/api/tasks` 是它的简化版       |
| **Potree**       | 大点云 **web 查看器/库**（八叉树 LOD + 测量标注）       | 我们 panel 的同行；也是我们**最大短板（LOD 流式）**的现成答案                           |
| **SuperSplat**   | PlayCanvas 的**高斯泼溅查看/编辑器**                    | 同属"3D 编辑客户端"，但数据类型（泼溅 vs 测量级点云）与目标不同                         |
| **我们的 panel** | 重建客户端（编辑器）+ 三端口生态（面板/官网/服务商）    | 唯一同时具备"采集→重建→测量→标注→账号→**计费**"的形态                                   |

## 3. 三条结论

### 3.1 该抄的三样（我们缺）

1. **`/info` 能力自述**（NodeODM）：把"这台有几个执行单元、队列多深、能收多少张图"变成**可查询事实**
   —— 正是"执行单元与硬件相关 + 总队列"这一设计要求的标准化表达；
2. **`/options` 参数自述**：处理参数变成**运行时协商**，客户端不再写死 `resolution` / `frame_count`；
3. **Potree 的 LOD 流式**：我们最大短板（一次性渲染子集，上限 `OMNI3D_MAX_RENDER_POINTS`）；
   WebODM 也是直接内嵌 Potree 看大点云 —— 做法在被验证过的路径上。

### 3.2 只有我们有的（不能指望现成轮子）

- **计量计费与控制面**：账号 → 计量 → 计费 → 发 Key → 流水 → 扣押产物，开源界**一个都没有**
  （WebODM 有账号/配额但无计费；Replicate cog / HF / Fal 有托管契约但无计费逻辑）；
- **多服务商凭据**（各家账号独立，不共用）；
- **服务端算的测量 + 全量点云吸附**（数值唯一真相，客户端说的数值不作数）；
- **AR 米制位姿驱动的真实尺度**（两条尺度路径）。

### 3.3 许可红线（重要）

- **WebODM / NodeODM 是 AGPL-3.0**：可以**照着协议的形状**实现（接口/规范形状不受版权保护），
  但**不能**把它们的代码拷进我们的产品，否则会被 AGPL 传染；
- **Potree / SuperSplat 是宽松许可**：前端库层面可以考虑直接用（以各自仓库 LICENSE 为准）。
