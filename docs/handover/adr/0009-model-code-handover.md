# ADR-0009：模型代码交接方式

- 状态：**Proposed**（三种方案都有代价，必须先做一次"上游复现 spike"再拍）
- 日期：2026-09-17
- 关联：ADR-0003、[`../../HANDOVER.md`](../../HANDOVER.md) §7

## 背景

事实（已核实，勿凭印象）：

- **权重是上游的**：`jedyang97/Fast3R_ViT_Large_512`（`model.safetensors` **2.47 GB**），
  **未入库**（被 `.gitignore` 挡住）。没微调过。
- **模型代码不是纯上游**：`fast3r/` `dust3r/` `croco/` 是 vendored 副本，且**有我们的本地修改** ——
  ① 大面积补中文 docstring；② **修过 `blocks.py` 的语法错误**（说明上游那个版本可能跑不起来）。
- 参考实现里权重目录是"仓库内的 `jedyang97/`"，新架构必须改成**挂载卷 + 配置指向**（ADR-0003）。

推论：**"新仓库直接 `pip install 上游 Fast3R` 就行"这句话未被验证。**

## 决策（推荐：方案 A + 先做 spike）

| 方案                                 | 做法                                                                                                                                                                      | 代价                                                                       |
| ------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------- |
| **A. pin 上游 + 复现 spike**（推荐） | worker 依赖上游 pin 到具体 commit；权重 pin **revision** + 记录 hash；**先跑一次干净环境复现**（同一段视频 → 点数/位姿与基线一致）；复现不过就把我们的修复做成 patch 文件 | 需要一次 spike（半天）；若上游确实跑不通则退化为 B                         |
| **B. vendor 我们验证过的快照**       | 把当前 vendored 副本原样搬进新仓（`vendor/`），`worker/README` 写清来源 commit                                                                                            | 最可复现；但新仓多一堆模型代码，且与上游脱钩                               |
| **C. 打成 `omni3d-model` wheel**     | 从归档仓打出 wheel（含我们的补丁），worker 依赖版本号                                                                                                                     | 版本锁最硬、边界最干净；需要先给研究仓加打包（本仓已归档，改起来另起分支） |

**无论选哪个**，都必须记录：上游 commit / 权重 revision + hash / 我们对 vendored 代码的改动清单
（docstring 与 `blocks.py` 修复）。

## 代价与后果

- 选 A 的隐藏风险：上游某次改动会让"可复现"悄悄失效 → 必须把**数值基线测试**放进新仓 CI
  （点数、`num_points_removed`、SOR 前后、local/global 对照，阈值见 `HANDOVER.md` §3.5）；
- 选 B/C 的隐藏风险：**没人知道这段代码从哪来**（除非按上面要求写清来源）；
- 任何方案都要把"训练/微调"排除在范围外（我们不改权重）。

## 未决

1. 上游复现 spike 的**验收标准**：同一输入下点数与位姿在什么容差内算通过（建议先记录参考实现的原始输出作为 golden）；
2. 权重交付方式：HF revision pin + 客户机预置，还是随镜像分发（体积 2.5 GB，建议挂载卷 + 首次下载校验 hash）；
3. 将来若接第二/第三个模型（体素 / 网格 / 泼溅），worker 是否统一走"模型清单 + 路由"。
