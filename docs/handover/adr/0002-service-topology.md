# ADR-0002：服务拓扑 —— Portal / Api / 静态面板 三服务

- 状态：Accepted
- 日期：2026-09-17
- 关联：ADR-0004（账务归属）、ADR-0005（热路径）、[`../02-wire-protocol.md`](../02-wire-protocol.md)

## 背景

参考实现是三个端口、两个部署形态的混合体：面板页面（静态）、官网（账号/计费/Key）、
服务商 API（重建）。它们**共享同一份 SQLite 文件**——这只在"同机"时成立。

真实存在的两种部署形态：

1. **官方**：官网卖服务（账号 + 计费 + 发 Key）+ 官方 provider（跑模型）；
2. **客户自建**：只要一个 provider + 面板，不需要官网与计费。

## 决策

拆成**三个可独立部署的服务**，共享一个类库（`Omni3D.Shared`：契约 DTO、鉴权、Key 校验客户端）：

| 服务                                  | 职责                                                                         | 依赖                                 |
| ------------------------------------- | ---------------------------------------------------------------------------- | ------------------------------------ |
| **Omni3D.Portal**                     | 控制面：账号、计费、发/吊销 Key、流水、官网页面                              | Postgres                             |
| **Omni3D.Api**                        | 数据面：作业、会话、点云/产物、几何测量；**经内部 API 调 Portal** 校验与上报 | Postgres（数据面 schema）、S3/MinIO  |
| **静态面板**（`Omni3D.Web` 构建产物） | panel 前端资源                                                               | 无（CDN/对象存储/或由 Api 顺带托管） |

- 三者通过**配置**决定启用哪些能力（`ROLE=official|provider` 思路保留，但**以服务为单位**部署，
  不是"一个二进制两个角色"——评审时明确否决了单二进制双角色）；
- 跨机器部署时**不允许共享数据库文件**：Portal 与 Api 之间的调用走**内部 API**（见 ADR-0004）。

## 代价与后果

- **多一跳网络**：Api 校验 Key 与上报用量都要过 Portal（见 ADR-0004/0005 的补偿办法）；
- **单机小客户**也要起两个进程（可退化为同一台机器、同一 Postgres 实例的不同 schema/角色）；
- **部署描述变多**（compose 至少三份服务定义），换取"官方/自建"两种形态同一套代码；
- 面板静态资源**不再由 API 托管**（保留一个 `ServePanel` 开关做开发便利）。

## 未决

- Portal 与 Api 是否允许"同一进程内挂载"作为开发模式（建议允许，仅限 `Development`）；
- 静态面板的交付：对象存储 + CDN，还是 Api 托管（影响 CORS 与缓存策略）。
