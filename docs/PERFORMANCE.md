> 复现：`.\run.ps1 bench`（全部示例）或
> `.\run.ps1 bench --frames 4 8 12 --res 224 512 --repeat 3`
>
> 脚本：`scripts/bench_reconstruct.py`

| 项   | 值                                                              |

| GPU  | 本机 CUDA（`torch.cuda.is_available() == True`）                |

## 速度

**结论：`512px` 约 0.17 s/帧，`224px` 约 0.05 s/帧（约 3.4× 差距）。**

按分辨率的中位数（n=15）：

| 分辨率 | 每帧耗时（中位） | 12 帧端到端 |
| ------ | ---------------: | ----------: |
| 224    |    **0.05 s/帧** | 0.5 ~ 0.9 s |
| 512    |    **0.17 s/帧** | 2.0 ~ 3.5 s |

## 质量（**代理指标**，非绝对精度）

⚠️ 本机**没有 GT 点云/位姿数据集**，因此下面衡量的是**自洽性与稳定性**，
不能等同于绝对精度。绝对精度需跑 vendored 的 `fast3r/eval/`
（依赖 re10k / robustmvd 数据集，本机未附）。

| 指标              | 含义                                                       | 理想                                 |
| ----------------- | ---------------------------------------------------------- | ------------------------------------ |
| `residual_ratio`  | local head 与 global head 对齐后的残差 RMS ÷ 点的 RMS 半径 | 越小越自洽                           |
| `local_scale_std` | 各视图 local→global 拟合缩放的离散度                       | 越小越一致                           |
| `mean_conf`       | **所选 head** 的平均置信度（随 `source` 走）               | 仅作参考，两档量纲不同，**不可互比** |

观测（30 组）：

- `residual_ratio` 中位 **0.0251**，范围 **0.0100 ~ 0.0981**
- 最好：`kitchen`（残差 0.010、尺度离散 0.0012、置信度 17.3）
- 最差：`family`（4 帧 224 时残差 0.096）、`lighthouse`（尺度离散 0.066~0.078 最高）
- 分辨率提升会明显改善自洽性：例如 `family` 4 帧 224→512，残差 0.096→0.044；
  12 帧 512 时残差降到 0.028

### 点云来源：local head vs global head（#21）

`OMNI3D_PTS3D_SOURCE` 环境变量（或 `run_reconstruction(..., pts3d_source=...)`）
可选两档，默认 `local`：

- `local`（**默认**）→ `pts3d_local_aligned_to_global` + `conf_local` ——
  local head 经 `align_local_pts3d_to_global` 对齐到全局坐标系；
  与上游重建评测口径一致（`configs/model/fast3r.yaml` 的
  `eval_use_pts3d_from_local_head: true`）。
- `global` → `pts3d_in_other_view` + `conf`（全局 head 原始输出）。

两者都在**同一全局坐标系**，下游（米制尺度变换 / 置信度过滤 / PLY / 渲染）
无需区分；且**一次前向同时产出两种输出**，因此切换**零成本**（无需重跑模型）。

实测（`family` 16 帧 @512，单次前向 4.3 s，16 视图）：

复现：`python scripts/ab_pts3d_source.py`。总点数存在 <0.1% 的跑次间波动
（cuDNN 非确定性 + 位姿估计），几何一致性结论稳定。

| 项                                       | `local`（默认）             | `global`                    |
| ---------------------------------------- | --------------------------- | --------------------------- |
| 过滤前总点数                             | 2,359,296                   | 2,359,296                   |
| 过滤后总点数（`VIS_CONF_PERCENTILE=10`） | 2,123,463                   | 2,123,908                   |
| 单视图点数（min/中位/max）               | 132,710 / 132,715 / 132,726 | 132,712 / 132,718 / 133,089 |
| 过滤后均值置信度                         | 18.78                       | 13.99                       |
| `residual_ratio` 中位                    | **0.027043**                | **0.027043**                |
| `local_scale` mean ± std                 | 0.485676 ± 0.034830         | 0.485676 ± 0.034830         |

结论：

1. `residual_ratio` 与 `local_scale*` **两档完全相同** —— 它们在对齐阶段算出，
   与「取哪个 head 出点云」无关，因此**不能**用它们区分两档优劣。
2. 两 head 的点云几何差异极小：中位最近邻距离 **0.00249**，仅占场景对角线
   （7.86）的 **0.032 %**（对称 Chamfer 中位同为 0.032 %）。即本机场景下两档
   几乎给出同一份重建，切到 `local` 主要是**与上游评测口径对齐**，
   而非一次肉眼可见的精度提升。
3. `mean_conf` 两档为 18.78 / 13.99，**量纲不同、不可互比**，
   只能在同一档内做纵向/横向对比。

## 实践建议

| 场景                            | 建议                                                      |
| ------------------------------- | --------------------------------------------------------- |
| 快速预览 / 迭代（同效果看一眼） | `224`，4~8 帧（≈0.2~0.6 s）                               |
| 正式出点云                      | `512`，10~16 帧（≈2~3.5 s，点数 1.5M~2.4M）               |
| 纯网页无 AR 位姿                | 任意尺度，需「标尺校准」                                  |
| 有 AR 位姿                      | 服务器自动对齐到米制（见 `docs/ARCHITECTURE.md` 第 6 节） |

> 速度瓶颈在 ViT 编码，与帧数近似线性；分辨率影响约平方级（512 是 224 的 ~3.4 倍时长）。
