# ADR-0007：结果与产物传输 + 点云 LOD

- 状态：**Proposed**（有推荐，待评审；panel 阶段先用哪套必须尽快定）
- 日期：2026-09-17
- 关联：[`../02-wire-protocol.md`](../02-wire-protocol.md) §3/§5/§7、[`../01-industry-research.md`](../01-industry-research.md) §1.2

## 背景

参考实现的传输方式有三个硬伤：

1. **上传**：一次性 multipart（先全读进内存再落盘）→ 大文件/弱网必崩；
2. **结果**：点云以"渲染子集 JSON"一次性下发，**上限 6 万点**（`OMNI3D_MAX_RENDER_POINTS`）——
   真实点云 200 万点，所以"看到的"永远不是"全量"；
3. **产物**：PLY 从本机磁盘路径直发，**没有签名 URL、无法分片续传、也没法扣押**（除非整站挡住）。

调研结论：**数据/产物层的标准最成熟**（3D Tiles 是 OGC 社区标准、COPC 是 OGC 社区标准、
glTF 是 Khronos 标准、PLY/LAS/LAZ 是事实/行业标准），**不该自研新格式**。

## 决策（推荐方案，待评审确认）

| 环节         | 决策                                                                                                                  |
| ------------ | --------------------------------------------------------------------------------------------------------------------- |
| 上传         | **预签名直传对象存储**（S3/MinIO），可分片/并发/单帧重试；元数据用 `POST /v1/uploads` 申请                            |
| 交付清单     | 任务 JSON **只放清单与指针**（`artifacts[]`：name/kind/format/bytes/url/expires_at），不放点云本体                    |
| 产物格式     | **PLY（float64 小端 + RGB）** 作为互操作基线（沿用冻结口径）；**COPC** 作为 GIS/流式补充；网格/纹理（glTF）待管线支持 |
| 浏览器流式   | **3D Tiles 1.1**（`tileset.json` + glTF/`.pnts`，可选 Draco/meshopt 压缩），前端用 **CesiumJS 或 Potree** 消费        |
| 兜底自研格式 | 八叉树 `manifest.json` + 每块二进制（布局见线协议 §5），**仅当不愿引 3D Tiles 时**使用；两种不得同时存在              |
| 坐标精度     | 渲染坐标**必须减掉局部原点**（任务中心）再 float32/量化；否则米制世界坐标下 float32 只剩厘米级抖动 → 量出的尺寸会漂   |
| 扣押         | 产物 URL **按需签发**且**短时有效**；账号 `arrears` 时不签发（见 ADR-0005）                                           |
| 大文件下载   | 预签名 URL 支持 `Range` 续传；前端显示进度与可恢复                                                                    |

## 代价与后果

- **要写一个"点云 → 3D Tiles/COPC"的转换步骤**（PDAL / py3dtiles / 自研），
  在 worker 出点云之后、交付之前；这一步是新增的 CPU 成本与失败点；
- **对象存储成为必需组件**（客户自建也要 MinIO 或本地卷兜底，见 ADR-0002/0004）；
- **前端要引 CesiumJS/Potree**（体积与学习成本），换来的是"真能看千万级点云"；
- **PLY 与 COPC 双产物**会让产物体积翻倍（可按客户配置只出一种）；
- **旧客户端的"6 万点渲染子集"契约作废**：属破坏性变更，必须写进迁移说明（panel 一起换掉，影响可控）。

## 未决

1. **3D Tiles / 自研分块 / COPC** —— 三选一（或组合）作为标准产物；panel 阶段先用哪个（建议：
   自研分块 + 合成点云先跑通交互，服务端阶段再产 3D Tiles）；
2. 转换放在 worker 内还是独立"产物服务"（影响重试与资源隔离）；
3. 是否需要"按视锥增量生成瓦片"（在线生成 vs 离线预生成）；
4. 泼溅（`.splat/SPZ/SOG`）是否作为**可选**产物格式接入（产品线问题，非架构问题）。
